# Authorization boundaries

`AuthContracts` in `src/auth` defines the interfaces and lifecycle signals using only Qt Core. `IAuthorizationService` describes session commands and token access for application composition. `AuthCore` implements `AuthorizationService`, coordinating injected `ITokenStore` and optional `IAuthorizationFlow` contracts; it does not read resources, construct OAuth objects, open a browser, or access Keychain. Models link `AuthContracts` without the concrete service or desktop adapters. `IsAuthorized()` requires a nonempty token in the live service. Missing or empty saved credentials request sign-in; user-denied Keychain access reports cancellation; storage and OAuth errors report failure.

`YandexAuth` supplies desktop adapters. `KeychainTokenStore` preserves the existing service/key identifiers and maps QtKeychain results into authentication errors. `QtOAuthAuthorizationFlow` validates `OAuthConfiguration` and loads the callback page when sign-in starts. It uses the configured loopback host, port, and path, lets Qt construct the authorization request, handles grant/error/browser-opening results, and closes the callback listener on completion or cancellation. Native job messages are never logged with credentials; the service exposes a hexadecimal diagnostic code to the UI.

`AuthorizationFactory` is used only by the application composition roots. The GUI chooses interactive authentication; the console CLI chooses saved-token access with no browser flow. Debug fixture mode constructs `FixtureAuthorizationService`, which uses only queued local signals and has no token or platform dependencies. Release builds exclude that implementation and reject fixture mode. The factory makes adapters children of the service so they share its lifetime; callers of the injectable core must keep their dependencies alive until it is destroyed.

`AuthorizationModel` in `src/models` preserves the existing `authorizationService` QML context API. It forwards commands and lifecycle signals, and exposes no token accessor. `Main.qml` handles authorization navigation once. GUI logout resets home, scenarios, account data, and the current device. Account requests and device-session operations carry a generation so old-session responses cannot repopulate cleared data or restart device polling after logout. The device generation advances only at authentication reset, preserving the existing selection and polling behavior within one login session.

The Yandex APIs keep their existing token-provider callbacks. Providers only return the current token and have no application-exit side effects. A missing token yields an HTTP-style 401 error before transport is invoked; the API layer does not depend on authentication implementations.

## Asynchronous contract

Stores and flows deliver one result per operation while its QObject context is alive. Canceling a browser flow releases its listener and suppresses the canceled completion. The session service correlates attempts, rejects late reads/grants after a replacement or logout, and suppresses duplicate in-flight commands. Logout clears the in-memory session and emits `logout` immediately. If a token write is pending, deletion starts after that write completes. `logoutFinished` means deletion succeeded or the entry was already absent; `logoutFailed` means secure storage could not remove it, while the in-memory session remains cleared. Sign-in is blocked until the pending logout completes. A write failure retains the valid in-memory session, matching the existing sign-in behavior, and records the storage diagnostic code.

`Authorization` exercises the core and QML model through scripted dependencies, including inline completion and stale replies. `OAuthAdapter` checks malformed configuration, setup errors, cancellation, context lifetime, and GUI/CLI composition without platform credential access or live network requests. `ApiFixture`, `All`, and the CLI process tests cover application integration. All are registered with CTest and included in the Windows Debug/Release/PCH matrix; the core tests also run in the Linux portable build.
